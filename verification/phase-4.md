## Scope and implementation

Reviewed BUILD_PLAN.md execution contract, renderer, TypeScript, source asset, token/component contracts and verification/phase-3.md before implementation. Only Phase 4 was implemented. The six existing products, variants, catalog filters, favorites, SQ/EN/DE, local PhotoSwipe galleries and demo previews remain. Four prescribed products with two illustrative views each were added: hidden anthracite door, classic walnut laminate, smoke-glass door, Scandinavian grey laminate. There are now ten published products, thirty localized detail routes, three catalog routes and three Studio routes.

Studio has two fixed photographic scenes, seven door finishes and five floor collections, separate door/floor/frame/skirting controls, 0/90° rotation, comparison, reset, URL restoration, product-to-Studio links and inquiries tied to completed frames. A smoke-glass photographic insert replaces the whole original leaf/casing/handle region and forces black profile. The hidden scene has no simulated standard casing.

The pure Canvas 2D renderer uses normalized inverse homography, sRGB/linear LUTs, linear mipmaps, wrapped bilinear/trilinear sampling, linear diffuse interpolation and coverage composition. Browser, worker, main-thread batches and Node fixtures share renderRows. No runtime WebGL, WebGPU, external service, animation loop, camera upload, pricing or AI inference was introduced. Worker cancellation and decode races are guarded by request IDs. Active-scene arrays are released on scene change, decoded textures are bounded to768px, result LRU is10MiB, settled output is capped at960px and previews at480px. Retry retains the completed canvas. Development Strict Mode cleanup is handled without disabling Strict Mode.

The root inquiry provider receives only scene ID/name, not calibration/surfaces. Studio is dynamically loaded. Product links carry actual selected finish IDs; product pages explain that room dimensions are representative. Scene changes push history; debounced finish/mode changes replace it. The existing pd:querychange event updates language links. All contacts remain demo previews, including telephone. No deployment or live contacts; Phase 5/offline was not implemented.
